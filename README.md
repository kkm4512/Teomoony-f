# Teomoony-f

터무니 단지 조회 화면 — **검색 · 지도 · 필지 폴리곤 · 단지 상세**

Docker 로 띄운 MSSQL(`Teomoony`)을 그대로 읽습니다. 로컬 실행 전용입니다.

```
브라우저 ──> Express (:5173) ──> MSSQL (localhost,11433)
                  │
                  └─ public/  바닐라 JS + Leaflet (빌드 없음)
```

브라우저는 MSSQL 에 직접 붙지 못하므로 Express 가 중간에서 API 로 바꿔 줍니다.

**데이터가 DB 에 들어 있어야 합니다.** 시군구 하나를 통째로 넣으려면:


```powershell
# 3) 건축물대장 + 단지가 적재됐는가 (이미 하셨으면 건너뜀)

# 4) 연속지적도 폴리곤 적재  <-- 지도에 필수

```

```
법정동(대장)   126      종로 87 + 성북 39
기본개요   264,025
단지        54,064
필지        68,876    <- 종로 87 + 장위동만. 성북 나머지는 미적재
건물        49,092    <- 같음
```

목록에는 나오지만 지도에 못 그립니다. 채우려면 `load_cadastral.py --lawd <코드>`.

## 1. 실행

Node 18 이상이 필요합니다.

```powershell
node --version
# 없으면:  winget install -e --id OpenJS.NodeJS.LTS   (설치 후 새 PowerShell 창)

cd C:\Project\Teomoony-f
npm install
npm start
```

`http://localhost:5173` 을 엽니다.

### 설정

따로 할 게 없습니다. `..\Teomoony\.env` 를 자동으로 읽습니다
(`DB_*`, `VWORLD_KEY`). 키를 두 군데 적어 두지 않기 위한 구조입니다.

다르게 쓰고 싶을 때만 `.env.example` 을 `.env` 로 복사해 덮어쓰세요.

## 2. 화면

| 영역 | 내용 |
|---|---|
| 좌측 상단 | 단지명 · 주소 · 단지코드 검색. 총괄표제부 단지만 필터 |
| 좌측 중단 | 적재 현황 (단지 / 필지 / 건물 / 실거래) |
| 좌측 목록 | 동 수 많은 순. 클릭하면 지도가 그 단지로 이동 |
| 좌측 하단 | 단지 상세 — 썸네일, 실거래(평형별), **관리비**, 제원, 인허가, 동 목록, 건물, 필지, 공시지가 |
| 지도 | 단지 마커. 체크하면 필지·건물 폴리곤. **항공사진 전환 가능** |

### 단지 썸네일

상세 맨 위에 네모 세 개. 단지 폴리곤을 bbox 로 삼아 항공사진을 작게 띄웁니다.

```
[ 근접 항공 ]  [ 주변 항공 ]  [ 로드뷰 → ]
```

**조감이지 외관이 아닙니다.** 외관은 로드뷰인데 SDK 로 띄우면 단지당 쿼터를 먹으므로
카카오맵 링크로 새 탭을 엽니다(키·쿼터 불필요). 단지 외관 사진은 공공 API 에 없습니다.

### 관리비 — 138단지 중 51개만 화면에 옵니다

관리비는 **K-apt 축 위에만** 삽니다. 정식 단지 상세에서는 `gold.v_complex_kapt` 의
**추정 연결**을 타고 와야 하는데, 법정동 + 사용승인일이 **양쪽 모두 1:1** 인 것만
남깁니다. 같은 날 승인된 단지가 여럿이면 **둘 다 버립니다.**

```
관리비 있음   138
  화면 도달    51  (37%)
  미도달       87  (63%)   <- 연결이 1:1 이 아니어서
```

**느슨하게 풀지 않습니다.** 추측으로 이으면 다른 단지의 관리비가 사실처럼 붙습니다
(`..\Teomoony\정책.md` 4장에서 기각한 길입니다). 대신 **비는 이유를 화면이 말합니다**:

| 상황 | 화면 |
|---|---|
| 150세대 미만 | 아무것도 안 띄움 — K-apt(의무관리대상) 대상이 아닙니다 |
| 그 법정동에 K-apt 미적재 | "아직 적재되지 않았습니다" (종로구 전체) |
| 적재됐는데 연결 미확정 | "이 단지의 것이라고 확신할 수 없습니다" |

표시 규칙은 **세대당 금액으로만**, 그리고 **같은 법정동 + 같은 분양임대 구분**과
함께 보여줍니다. 분양/임대를 안 가르고 비교하면 틀립니다 — 임대 78,450원 vs
분양 113,098원입니다. `장충 잔액 0` 은 돈이 없는 게 아니라 **임대 · 신축 · 미적립**
셋 중 하나이고, 뷰가 `장충_잔액_상태` 로 그 뜻을 내려보냅니다.

### 대장 없는 신축

`gold.complex` 는 건축물대장에서만 만들어집니다. 대장이 아직 안 나온 신축은 단지가
없어 검색에도 지도에도 안 나왔습니다 — 장위자이레디언트 2,840세대가 그랬습니다.

K-apt 를 별도 축으로 띄웁니다. **점선 테두리 · 주황 · `대장없음` 배지**로 단지와
다르게 보이게 했습니다. 같은 모양이면 단지코드가 있는 것처럼 읽히고, 동 목록·필지가
비어 있는 것이 결손처럼 보입니다. 결손이 아니라 아직 대장이 안 나온 것입니다.

**단지코드는 발급하지 않습니다.** 대장이 나오면 정식 단지가 되고 이 목록에서 저절로
사라집니다. 실거래는 `aptSeq` 로 1~4단지까지 쪼개 보여줍니다 — **동 단위는
표시하지 않습니다**(동 이름이 대장에서 나오는데 아직 없습니다).

지도에서 필지를 클릭해도 그 단지가 선택됩니다.
**줌 15 미만에서는 필지를 그리지 않습니다** (한 번에 너무 많이 불러오지 않도록).

## 3. API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/health` | 적재 현황 |
| GET | `/api/config` | VWorld 키 보유 여부 (타일용) |
| GET | `/api/complexes?q=&recap=&limit=` | 단지 검색 |
| GET | `/api/complexes/:id` | 단지 상세 + 동/필지/건물/실거래 목록 |
| GET | `/api/complexes/:id/buildings` | 그 단지의 건물 외곽선 (GeoJSON) |
| GET | `/api/buildings?bbox=...` | 지도 영역 안의 건물 외곽선 (GeoJSON) |
| GET | `/api/complexes/:id/geo` | 그 단지의 필지 폴리곤 (GeoJSON) |
| GET | `/api/parcels?bbox=minLng,minLat,maxLng,maxLat` | 지도 영역 안의 필지 (GeoJSON) |
| GET | `/api/lawds?bbox=` · `/api/lawds/:lawd/geo` | 법정동 경계 + 요약 |
| GET | `/api/complexes/markers?bbox=` | 단지 마커 |
| GET | `/api/newbuilds?bbox=` | **대장 없는 신축** 마커 |
| GET | `/api/newbuilds/:kaptCode` | 신축 상세 + `aptSeq` 단지별 평형 집계 |

단지 상세(`/api/complexes/:id`)는 K-apt 참고 연결 · **관리비** · 건축인허가 ·
`v_trade_offsite` 를 함께 내려줍니다.

`/api/complexes?q=` 는 단지 · **법정동** · **신축** 을 함께 내려줍니다.

GeoJSON 은 `silver.cadastral_parcel.geojson` 에 저장된 문자열을 그대로 내보냅니다.
SQL Server 에는 `ST_AsGeoJSON` 이 없어서, 적재 시점에 GeoJSON 을 보관하고
연산용으로 `geometry` 컬럼을 따로 둔 구조입니다.

## 4. 알아둘 것

**좌표계** — VWorld 를 `crs=EPSG:4326` 으로 받으므로 위경도 그대로입니다.
변환 단계가 없습니다. 다른 소스를 추가할 때 5179(UTM-K)로 들어오면
적재 시점에 4326 으로 바꿔 넣으세요. 섞이면 지도에 엉뚱한 데 찍힙니다.

**VWorld 타일 도메인** — 키 발급 시 등록한 도메인에서만 동작합니다.
`localhost` 가 등록돼 있지 않으면 타일이 전부 실패하는데, 그 경우
자동으로 OpenStreetMap 으로 내려가고 안내가 뜹니다.

**필지가 없는 단지** — 연속지적도에 매칭되는 필지가 없는 단지는 지도에
그릴 수 없습니다. 목록에는 나오고, 선택하면 안내가 뜹니다.

**실거래 "없음" 은 네 가지입니다** — `gold.v_rtms_gap` 이 거래마다 이유를 분류합니다.

```
MASKED    22,169  지번이 '1**' 로 가려짐. 영원히 불가 (단독·다가구·토지·상업)
NO_BLD       819  그 지번에 대장이 0건 (신축 시차 · 나대지 · 멸실)
NO_TITLE      11  대장은 있는데 전유부뿐. 설계상 정상
offsite      128  단지는 있는데 신고 지번이 다름 (v_trade_offsite)
```

**신축(`NO_BLD`)은 화면에 띄웁니다.** 나머지 셋을 단지 상세에 드러낼지는 아직
정하지 않았습니다. 데이터는 준비돼 있습니다. 상세는 `..\Teomoony\정책.md` 6장.

**빈칸은 사유를 적습니다** (2026-10-16) — 값이 없어도 **줄은 항상 그립니다.**
없다고 줄을 지우면 "왜 비었지" 가 없어지는 게 아니라 **없다는 사실 자체가 없어집니다.**
브라운스톤 돈암의 주차 1,177대가 그렇게 사라져 있었습니다(총괄표제부를 안 보던 버그).

```
아직 적재 전      범위 밖입니다. 받으면 생깁니다
해당 없음         이 단지 종류엔 그 축이 없습니다
확인 불가         데이터는 있으나 이 단지 것이라 확신할 수 없습니다
원본에 값 없음    받아왔는데 그 칸이 공란입니다
⚠ 분류되지 않음   넷 중 아무것도 아닌데 비어 있습니다 -> **버그 신호**
```

**"준비중" 한 가지로 덮지 않습니다.** 그 말은 `아직 적재 전` 에만 해당합니다 —
지번 마스킹은 영원히 불가고, 150세대 미만 관리비는 해당 없음이고, 주차는 버그였습니다.
모든 빈칸에 그럴듯한 설명을 붙이면 **버그가 정상처럼 보입니다.**

`⚠ 분류되지 않음` 이 보이면 **제보해 주세요.** 사유 분류를 빠뜨린 자리입니다.
적용: 제원 전 항목 · 인허가 · 관리비 · 필지 · 건물 외곽선 · 실거래.

**단지 미지정 필지** — 지도의 회색 필지는 건축물대장에 잡히지 않은 땅입니다
(나대지 등). 단지에 속하지 않습니다.

**geography 가 아니라 geometry** — `geography` 는 폴리곤 링 방향이 반대면
지구 반대편을 덮는 도형이 되어 조용히 틀립니다. VWorld 가 어느 방향으로
주는지 보장이 없어 `geometry` 를 씁니다. 이 축척에선 평면 계산으로 충분합니다.
